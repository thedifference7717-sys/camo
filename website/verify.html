// VERIFY BEFORE YOU RUN · TAKES 5 MINUTES

Verify your download

Fake wallets are the most common way people lose coins. Before you run any CAMO download, check two things: that the list of file fingerprints (hashes) was signed by CAMO's release key, and that your file's fingerprint is on that list.

The only genuine release key: CAMO release signing <camocoin@proton.me>, fingerprint 5F1A 8350 C748 BC43 AD19 2472 AF13 7B28 E11A 0857. Get it from this site or keys.openpgp.org. A signature from any other key is not from CAMO, whatever its name says. Nobody from CAMO will ever DM you a download.

01 Download three things

From the official links on this site (or CAMO's GitHub releases): your package (Mac, Windows or Linux), the signed hash list SHA256SUMS.asc, and the public key camo-release.asc. Put all three in your Downloads folder.

02 Check the signature

Mac: install GnuPG (GPG Suite, or brew install gnupg). Windows: install Gpg4win and use its command prompt. Linux: gpg is usually already there. Then, in a terminal in your Downloads folder:

gpg --import camo-release.asc
gpg --verify SHA256SUMS.asc

You must see Good signature from "CAMO release signing <camocoin@proton.me>" and a primary key fingerprint ending E11A 0857 that matches the full fingerprint above. A warning that the key "is not certified with a trusted signature" is normal: it means you haven't personally vouched for the key, which is why you compare the fingerprint yourself. BAD signature, or a different fingerprint: stop and delete everything.

03 Check your file is on the list

Linux:

sha256sum --ignore-missing -c SHA256SUMS.asc

Your file must say OK. (Lines about "improperly formatted" are the signature text and can be ignored.)

Mac:

shasum -a 256 your-file-name

Windows (Command Prompt):

certutil -hashfile your-file-name SHA256

On Mac and Windows, open SHA256SUMS.asc in a text editor and find your file's name: the long code next to it must match yours exactly, every character. Any difference means the file was changed: delete it.

04 Why this works

Can't an attacker just put a fake hash list next to a fake file?
They can, but they can't sign it with CAMO's release key: that key never leaves the founder's computer. That is why step 02 matters most, and why the fingerprint must match the one printed here and on keys.openpgp.org.
Do I have to trust CAMO at all?
Less every release. The builds are reproducible: anyone can rebuild them from the public source code with contrib/gitian and get the same fingerprints, and independent builders publish theirs. If they match, nobody slipped anything in.
And on phones?
Install Ghillie for iPhone or Android only from the official app stores once it is released (Q1 2027), from the publisher named on this site. Never from a link someone sends you.
